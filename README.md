# 牙槽骨吸收测量标注软件

用于牙周病研究的批量标注与测量工具，支持**全景片**与**根尖片（小牙片）**两种片型。
读片 → 画框选牙 → 分步放大标 8 个点 → 四个公式同时出结果 → 批量导出。

当前 1.2 版增加自动分割人工标点、自动候选两个入口，共用原有四点/四公式。
使用 `dist/AI-integrated/牙槽骨吸收测量AI_安装包_v1.2.0-preview.exe`；
完整操作见 [1.2 使用说明](packaging/distribution/使用说明.md)，开发交接见 STATUS.md、HANDOFF.md。
自动候选的轮廓投影是几何校正，尚未验证解剖准确率；缺点需要人工补标。

## 计算方法（四个公式，界面可切换）

每个**测量位点** = 一个邻面（近中或远中），由 **4 个独立的点**确定，
按从咬合面到根尖的顺序标：

| 点 | 含义 |
|----|------|
| P1 | CEJ 釉牙骨质界 |
| P2 | CEJ 下 2mm |
| P3 | AC 牙槽嵴顶 |
| P4 | 根尖 |

近中与远中**各标各的 4 个点**（含各自的根尖）—— 磨牙近中侧用近中根根尖、
远中侧用远中根根尖，强行共享一个根尖会让多根牙的两侧长轴失真。
所以**一颗牙 8 个点**：第 1 颗 P1–P8，第 2 颗 P9–P16，第 3 颗 P17–P24。

### 四个公式

四个公式用**同一组手标的点**，差别只有两处：

|  | 分子取直线距离 | 分子取长轴投影 |
|---|---|---|
| **起点 = CEJ** | ① 直线法 | ② 投影法（默认） |
| **起点 = CEJ 下 2mm** | ③ 直线法·2mm | ④ 投影法·2mm |

终点从来不变：分子终点是牙槽嵴顶，分母终点是根尖。

```
① 比例 = ‖AC − CEJ‖      / ‖根尖 − CEJ‖
② 比例 = (AC−CEJ)·(根尖−CEJ)   / ‖根尖−CEJ‖²
③ 比例 = ‖AC − CEJ₂‖     / ‖根尖 − CEJ₂‖
④ 比例 = (AC−CEJ₂)·(根尖−CEJ₂) / ‖根尖−CEJ₂‖²      CEJ₂ = CEJ 下 2mm
```

**两种修正各自解决一个问题**：

- **投影（②④）**：AC 点通常偏在牙的侧方，直线法会把这段横向分量算进分子，
  牙齿越倾斜高估越多。数学上**直线法恒 ≥ 投影法**，两者之差就是倾斜带来的高估
  （`tests/test_core.py` 用 300 组随机点验证了这条不等式）。
- **起点后移到 CEJ 下 2mm（③④）**：生理性骨改建约占 CEJ 下 2mm，
  从这里起算可把它排除在「病理性吸收」之外。起点后移会同时缩短分子和分母。

> **标满 4 个点后四个公式的结果同时可得**，切换下拉框即可，永远不用重标。
> 导出的 CSV / Excel **四个公式的值都给**，外加「倾斜高估(①−②)」和
> 「起点差异(①−③)」两列，方便你在研究里量化两种修正各自的影响。
> 界面结果区也同时列出四者，当前生效的那个用 ● 标出。

**只标了 3 个点的旧数据**：①② 照常可算，③④ 会如实显示「缺 P2」，
位点表的「点」列会标 `3/4` 提示你哪一侧还差点。

**公式是项目级设置**，不是每张片各管各的 —— 一批研究数据里公式混用
会毁掉可比性。切换后全项目立即按新公式重算，选择写进 `project.json` 持久保存。

**不需要毫米标定**：分子分母同尺度相除，放大率自动约掉，比值是无量纲的。
（P2 那个「2mm」由医生在放大图上按经验点下去，软件不做毫米换算。）

### 患者级汇总

```
worst_ratio         = max(所有位点的 R)        ← 全口最重位点
bone_loss_age_ratio = worst_ratio / 年龄
```

软件输出这两个**数值**，外加骨吸收比例落在 2018 分类哪个影像学区间：

| 区间 | 骨吸收比例 | 部位 |
|------|-----------|------|
| 一 | `< 15%` | 冠 1/3 |
| 二 | `15% – 33%` | 冠 1/3 |
| 三 | `> 33%` | 根中 1/3 及以上 |

> ⚠️ **软件不输出 Stage / Grade 结论。**
> 2018 新分类的 Stage 需要缺牙数、探诊深度、根分叉、咬合创伤、咀嚼功能等
> 临床资料；Grade 还需要病史与危险因素（吸烟、糖尿病）。仅凭一张全景片给出
> I/II/III/IV 或 A/B/C 是不严谨的。区间只说明数值落点，最终判断由医生完成。

区间分界可在「设置」里改，改完点「全部重算」。

## 工作流

1. **项目 → 新建项目**，选一个空文件夹
2. 工具栏选**片型**：全景片 / 根尖片
3. 把片子**直接拖进窗口**（或 `Ctrl+I`）
   - 按文件内容 sha1 自动去重
   - 按文件名自然排序：`1, 2, 10` 而不是字典序的 `1, 10, 2`
   - **根尖片模式下，图片所在的文件夹名 = 病人**。所以「一堆病人文件夹、每个
     文件夹里若干张根尖片」整体拖进来就自动分好组了。
4. **项目 → 导入名册**，一次性带入全部年龄
5. 打开片子即进入**画框选牙**（也可按 `T` 切换）：拖出方框框住可疑牙
   > 框要包含**完整的牙冠 + 牙根 + 根尖**。框由你画，所以「不能残缺」由你直接保证。
6. `Enter` 开始**分步放大标定**，每颗牙 8 个点（一侧走完再走另一侧）：

   | 牙序 | 近中 CEJ / 2mm / AC / 根尖 | 远中 CEJ / 2mm / AC / 根尖 |
   |------|---------------------------|---------------------------|
   | 第 1 颗 | P1 P2 P3 P4 | P5 P6 P7 P8 |
   | 第 2 颗 | P9 P10 P11 P12 | P13 P14 P15 P16 |
   | 第 3 颗 | P17 P18 P19 P20 | P21 P22 P23 P24 |

7. `Ctrl+Enter` **完成本例并自动跳下一张**，左侧计数实时变动

### 两种片型的差别

| | 全景片 | 根尖片（小牙片） |
|---|---|---|
| 一个病人 | 一张片 | 一个文件夹里的多张片（全口可达 28 张） |
| 病人归属 | 文件名 | **所在文件夹名** |
| 「全口最重位点」 | 本片内取最大 | **跨该病人的所有片子取最大** |
| 年龄 / 性别 | 每张各自填 | 填一张，**自动同步给同病人的其他片子** |
| 导出汇总 | 一行一张片 | **一行一个病人**（带片数与最重所在片） |

导入后若文件夹结构不规整（同一病人的片子散在几个文件夹里），
在左侧列表多选 → 右键 →「归为同一个病人」手工并组即可。

### 左侧列表右键菜单

| 菜单项 | 说明 |
|--------|------|
| 打开 | 打开这张片子 |
| 重命名… | 改列表里显示的名字（不动磁盘文件名） |
| 归为同一个病人… | 多选时出现，根尖片模式专用 |
| 从项目移除… | 二选一：**仅移出列表**（文件保留，重新导入可接上）或**连同文件删除**（再确认一次，不可撤销） |
| 在资源管理器中显示 | 定位到图片文件 |

> 「引用模式」导入的原图**永远不会被删** —— 那是你自己的原始数据。

## ★ 换公式的成本

> **磁盘上永远只存原始点坐标，比值和分级都是运行时算出来的派生量。**

| 变更 | 代价 |
|------|------|
| 在四个公式之间切换 | 工具栏下拉框选一下 → **0 秒**，全项目自动重算 |
| 改区间阈值 | 设置里改 → 点「全部重算」→ **0 分钟** |
| 加**第五个**公式（只换算法，不加点位） | `app/core/formula.py` 加一个函数 + 一行装饰器 → **10 分钟**，下拉框自动出现，一键重算，**不用重标** |
| 加需要**新点位**的公式 | 半天：`models.ROLES` 加角色 + `Site` 加字段 + 这里加公式。标定步骤、P 编号、导出列都从 `ROLES` 自动派生，不用逐处改。旧数据缺新点位时，需要它的公式自动算不出、老公式照常可用 |

加一个公式长这样，界面下拉框会自动出现新选项：

```python
@formula("my_v1", label="我的新公式", needs=("cej", "ac", "apex"))
def my_v1(p, cfg):
    L = g.distance(p["apex"], p["cej"])
    h = ...
    return Metrics(root_length=L, bone_loss=h, ratio=h / L)
```

`app/core/formula.py` 底部有这两种扩展的完整注释示例（CEJ 下 2mm 就是照第二种加的）。

## 跨平台打包（macOS DMG）

**macOS 的 `.app` / `.dmg` 无法在 Windows 上生成** —— PyInstaller 不支持交叉编译
（要把目标平台的 Python 解释器和 Qt 框架原样打进去，这些 `.dylib` / `.framework`
在 Windows 上根本不存在），DMG 也依赖 macOS 自带的 `hdiutil`。

代码本身是跨平台的（PySide6 + OpenCV + numpy 三家都有 mac 版），
`build.spec` 已经写好了 macOS 分支，两条路任选：

### 路线 A：手边有 Mac

把整个项目拷到 Mac 上，跑：

```bash
bash build_macos.sh
```

自动建 venv → 装依赖 → 跑测试 → 打 `.app` → 自检 → 生成
`dist/牙槽骨吸收测量_v1.0.0.dmg`（带「拖到 Applications」的标准安装盘）。

### 路线 B：没有 Mac —— 用 GitHub 的 macOS 机器

`.github/workflows/build.yml` 已经配好。把项目推到 GitHub 后：

1. 仓库 → **Actions** → 选「打包」→ **Run workflow**
2. 跑完在该次运行的 **Artifacts** 里下载
   `牙槽骨吸收测量-macOS`（.dmg）和 `牙槽骨吸收测量-Windows`（exe + 安装包）

推一个 `v1.0.0` 这样的 tag 时会自动建 Release 并挂上全部文件，
把 Release 链接发给同事即可。公开仓库完全免费，私有仓库每月也有免费额度。

> **macOS 首次打开会被 Gatekeeper 拦**（没有苹果开发者签名，99 美元/年）：
> 提示「无法打开，因为无法验证开发者」。让对方**右键点图标 → 打开 → 再点「打开」**，
> 只需这一次，之后正常双击。要彻底免掉这一步得买开发者证书做签名+公证。

## 已知边界

- **牙槽嵴顶曲线功能已停用**。在真实全景片上准确度达不到临床可用，个别片子会
  贴着牙冠走，作为「定位可疑牙位」的辅助反而可能误导。代码保留在
  `imaging/bonecrest.py`（含踩坑记录），界面上已完全摘掉。
- **牙位号是几何推断的**（上下颌 + 中线分象限 + 弧长排序），牙列完整时基本准确，
  缺牙 / 阻生时会偏一位 —— 界面上是可改的输入框，直接敲正确的号即可。
- 自动分割（YOLO-seg ONNX）**尚未接入**，接口已预留在 `imaging/segmenter.py`。
  调研发现公开的全景片权重几乎都只有单类 `tooth`、不带 FDI 牙位号，
  详见 `docs/架构与需求.md` §14。
- `h < 0`（AC 在 CEJ 冠方，未见吸收）**如实存负值不截断为 0**，避免统计偏倚；
  `R > 1` 给黄色告警但不阻断。
- **根尖片模式下年龄会同步**：一个病人十几张片子逐张填年龄既费事又容易不一致，
  而年龄不一致会让同一个病人算出不同的「骨吸收年龄比」。所以填一张即同步全部。
- **标注安全阀**：保存时若牙位数比盘上已有的少，会先在 `annotations/_backup/`
  留一份带时间戳的副本（保留最近 20 份），任何误清空都能找回。
